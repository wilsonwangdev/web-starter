# 维护这个 Web 应用

先读根目录 `AGENTS.md`、`package.json` 和 `CONTRIBUTING.md`。依赖版本、命令和实际配置以仓库文件为准，不从技能复制固定版本。

按任务读取需要的上下文：

- 创建派生项目：`docs/start.md`；确定项目身份、用户和第一条真实流程，再修改示例。
- 页面、组件和交互：`docs/design.md`；先沿用语义变量、`packages/ui/` 的成熟基础组件和既有状态。组件包的公开入口、样式与主题约定在设计和架构说明维护。视觉审查或改版按其中的可选设计辅助流程，保留改前状态并核实外部诊断。
- 新增页面、共享状态、业务流程或修改工程配置：`docs/architecture.md`；先明确职责与状态归属，再沿已有模块接线，入口保持组装职责。
- 托管或安装能力：`docs/deployment.md` 与架构中的安装范围；区分本地模拟、真机与线上证据。

沿实际调用链修改，先检查已有能力，不为局部任务重建工程。新增文案同时维护语言资源，新增界面覆盖窄屏和亮暗状态；涉及持久化时处理损坏、写入失败和迁移。

为改变的行为选择 Node、真实浏览器或生产构建验证，完成仓库要求的检查。检查结果与未验证边界在交付中说明；运行日期、统计、截图及个人偏好不能沉淀为通用规则。

改动使用主题分支和 PR。面向公开仓库的代码与文档自包含，不要求特定个人技能、另一个业务项目或本机路径；凭据、真实内容和临时说明留在被忽略的本地材料。
